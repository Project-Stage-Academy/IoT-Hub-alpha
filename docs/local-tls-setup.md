# Local TLS Development Setup

This guide outlines how to set up a local development environment that uses Nginx as a reverse proxy to provide HTTPS, using a locally-trusted certificate generated by `mkcert`.

## 1. Prerequisite: Install mkcert

You must have `mkcert` installed on your local machine.

- **On Windows (using Chocolatey):**
  ```bash
  choco install mkcert
  ```

- **On macOS (using Homebrew):**
  ```bash
  brew install mkcert
  ```

- For other platforms, refer to the [official mkcert installation instructions](https://github.com/FiloSottile/mkcert#installation).

## 2. Create a Local Certificate Authority (CA)

After installing `mkcert`, you need to create and install your own local CA. This makes the certificates you generate trusted by your browsers. This is a one-time command.

```bash
mkcert -install
```

## 3. Generate the Certificate for Localhost

Next, generate the certificate that the Nginx proxy will use.

1.  From the project root, create a directory to hold the certificate files:
    ```bash
    mkdir -p nginx/certs
    ```

2.  Navigate into the `certs` directory and generate the certificate files for `localhost`.
    ```bash
    cd nginx/certs
    mkcert localhost 127.0.0.1 ::1
    cd ../..
    ```
    This creates the `.pem` files that Nginx will be configured to use.

## 4. Configure the Nginx Proxy

The `nginx` directory contains three key files that you have set up:

- `nginx/Dockerfile`: A file that builds the Nginx container by copying in a custom configuration.
- `nginx/nginx.conf`: The configuration file that tells Nginx how to handle HTTPS traffic and forward it to the Django `web` service.
- `docker-compose.yml`: This file was modified to include a `proxy` service that uses the Dockerfile and configuration above. It also removes the direct port mapping from the `web` service.

## 5. Run the Application with TLS

With all the configuration in place, you can now build and run the entire stack.

1.  **Build and Start the Services:**
    From the project root, run the following command. The `--build` flag is important as it tells Docker to build the new `proxy` image.
    ```bash
    docker compose up -d --build
    ```

2.  **Access the Application:**
    Once the containers are running, you can access your application securely at:
    [https://localhost](https://localhost)

    Your browser should show a padlock icon and no certificate warnings.
